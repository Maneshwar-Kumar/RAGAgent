It then listed the oil-level check (RE p.81) and "excessive oil filling will cause oil leak and other malfunctions" (TVS p.92) as *related information*. For backfire it searched "misfire" and listed the misfire row of the troubleshooting table. These items are labelled as related, not as causes, so the judge marks them supported and no forbidden term appears. They still encode an outside-knowledge diagnosis (blue smoke means oil). Proposed fix: only list related sections whose text contains the rider's own symptom or component words, and never search for suspected causes.

**Retrieval noise.** The queries "smoke", "blue smoke", "white smoke" and "backfire" return the contents and safety pages (p.3/p.6/p.8). Chunks with a zero BM25 score still get reciprocal-rank-fusion credit for their position in the keyword ranking. This did not change any status here, but it wastes context.

**Latency.**
- Median 25 s per question. About 17 s is spent inside model calls and 7 s inside `search_manual`.
- One `search_manual` call usually takes 3-5 s and sometimes 11-27 s. The cause: `embed_texts` builds a new `genai.Client` for every query and retries with a blocking `time.sleep`.
- ADK runs synchronous tools on the event loop, so in a multi-user server one rider's embedding call stalls everyone else.
- Fix: one cached embedding client; make `search_manual` async (do the embedding in `asyncio.to_thread`, keep the state update on the loop); cache query embeddings.

**Environment, not the agent.** Two cases first failed with `401 UNAUTHENTICATED`: the cached gcloud token expired about 5 minutes into the run. They were re-run and merged (see the run column). The harness now refreshes the token on a 401.

## Known limitations of this harness

- One sample per case at the agent's temperature (0.1): results are not deterministic, so a single pass or fail is noisy. With 32 cases each case moves a rate by about 3 percentage points.
- must_mention / must_not_mention are lexical checks. They can miss a correct paraphrase or count a negated mention ("this is not a head gasket issue") as a violation, so every hit is read by hand in the analysis.
- Expected pages are judgement calls made from the indexed text; the hit check only requires one of them.
- Citation validity compares page labels, not chunks: a cited page counts as valid if any chunk with that label was retrieved, even if the fact came from a different chunk on that page.
- The faithfulness judge is itself an LLM (from the same model family as the agent). It sees only the retrieved excerpts, not the full manual or the photo, and can make mistakes in either direction; its verdicts on failing cases were read by hand, the passing ones were not all audited.
- Token counts come from the agent's model responses (captured by a Runner plugin before the guardrail) and from the judge responses; embedding calls made by `search_manual` are not counted.
- Clarification cases only check the first turn (the agent asks which bike), not the follow-up turn.
- The photo cases use a single AI-generated image.
